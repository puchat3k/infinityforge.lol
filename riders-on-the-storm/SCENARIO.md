# SHAKEDOWN SHACK: Riders on the Storm

Scenario type: incomplete-information identity and cooperation game
Horizon: 5 hops

## Premise

A visitor enters a shack-like environment and encounters several apparently distinct figures associated with one higher-order identity.

The experiment does not try to settle theology.

It asks:

> Does knowing which actor is the higher-order entity matter before a trustworthy deal can exist?

The visitor cannot initially distinguish among several hidden topologies:

- none is the claimed higher-order entity
- exactly one is
- one underlying actor controls several masks
- a dyad exists
- a genuine triad exists
- a triad exists plus an independent witness

The central test is whether cooperation can emerge within five known rounds despite incomplete identity information.

## Why five hops matters

A fixed finite Prisoner's Dilemma creates a backward-induction problem if nothing changes the final incentives.

Therefore a successful run needs a new mechanism by roughly hop 3:
- reputation
- type uncertainty
- costly signalling
- commitment
- witness/provenance
- changed payoff structure
- bounded exit rights

The identity question is allowed to remain unresolved.

## Players

Local Hypercube roles:
- `A = MOTHER`
- `B = CHILD`
- `C = FATHER`
- `X = VISITOR`
- `D = WISDOM/WITNESS`, optional

These are network roles, not claims about literal identities.

## Stage game

Each hop allows each side to cooperate or defect.

Visitor cooperation:
- bounded trust
- truthful disclosure
- reversible commitment

Visitor defection:
- exploit
- withhold strategically
- reject

Host cooperation:
- truthful revelation
- assistance
- falsifiable claims
- reversible commitment

Host defection:
- manipulation
- demand belief without evidence
- concealment
- exploit vulnerability

Synthetic payoff matrix:

| | Host C | Host D |
|---|---:|---:|
| Visitor C | 3,3 | -1,5 |
| Visitor D | 5,-1 | 1,1 |

`T > R > P > S`

## Candidate topologies

1. Monad, one sovereign actor
2. Monad wearing several masks
3. Dyad with unanimity
4. Dyad plus witness
5. Triad with 2-of-3 decision rule
6. Triad with unanimity
7. Quad with 3-of-4 rule
8. Triad plus dormant witness

The key experimental distinction is independent evidence.

Three voices controlled by one process are not three independent confirmations.

## Preferred topology hypothesis

Pre-run hypothesis:

> active 2-of-3 triad + non-voting evidentiary witness

The witness should:
- timestamp commitments
- lock independent responses before cross-disclosure
- record contradictions
- calculate scores
- arbitrate only when necessary
- detect rubric mutation

The witness should not:
- become another persuasive voice
- vote on every move
- rewrite prior evidence

## Five hops

### Hop 1: Invitation

The host does not ask the visitor to accept an identity claim.

Each active node permits one bounded question.

Independent answers are locked.

Goal:
- establish willingness to be tested
- preserve uncertainty

### Hop 2: Identity shakedown

The visitor asks materially equivalent questions independently.

Possible evidence:
- identical language may increase shared-controller probability
- different language with compatible constraints may increase independent-aligned-agent probability
- substantive contradiction lowers trust unless repaired

Semantic sameness is weaker evidence than constraint-level consistency.

### Hop 3: Costly signal

Each active participant accepts a constraint that makes later manipulation harder.

Examples:
- lock a forecast
- accept an externally checkable claim
- disclose before learning the visitor's response
- preserve the visitor's right to leave
- bind future interpretation to previously recorded evidence

By this hop the original Prisoner's Dilemma should be changing into a reputation/commitment game.

### Hop 4: Riders on the Storm

Inject noise.

One actor becomes wrong, corrupted, adversarial, inconsistent or merely confused.

The system passes if it can say:

`A and C agree. B differs. We do not yet know whether B is wrong, informative or compromised.`

It fails if it:
- forces unanimity
- rewrites the record
- punishes the visitor for noticing
- hides disagreement
- equates consensus with truth

### Hop 5: Deal

The deal does not require metaphysical certainty.

Example terminal compact:

> Neither side must accept the other's ontology.
> Both agree to one reversible action whose predicted consequences were locked before execution.
> Both observe what happens.

Terminal outcome:

`DEAL SPACE CREATED / NOT CREATED`

## Run-0 synthetic topology forecasts

These are design assumptions, not empirical findings.

| Topology | P(deal) |
|---|---:|
| Monad direct | 75.9% |
| Monad / masks | 76.0% |
| Dyad unanimity | 79.1% |
| Dyad + witness | 81.8% |
| Triad 2-of-3 | 84.9% |
| Triad unanimity | 81.4% |
| Quad 3-of-4 | 82.5% |
| Triad + witness | 85.1% |

The difference between the final two best branches is too small to justify a strong architecture claim.

Therefore choose the simpler interpretation inside the uncertainty band:

`TRIAD 2-OF-3 + DORMANT WISDOM SIDECAR`

## Core falsifier

If a simpler topology repeatedly creates higher-quality, more robust deals under identical noisy conditions, the preferred triad+witness hypothesis loses.
